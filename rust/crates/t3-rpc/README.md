# t3-rpc

Portable Effect RPC transport for native and `wasm32-unknown-unknown`. The crate
has no runtime, socket, thread, or platform clock dependency. Payload, success,
and typed error types are generic (defaulting to `serde_json::Value`); it does
not depend on `t3-contracts`.

Regenerate the reference transcripts from the repository root:

```sh
node rust/tools/export/rpcTranscripts.ts
```

The exporter uses the installed Effect version, its actual JSON serializer,
schema-aware `RpcClient.make` and `RpcServer.make`, and paired in-memory
`Socket`s running `makeProtocolWithHttpEffectWebsocket`, including upgrade
headers and the real `splitLargeSocketFrames` / `joinSocketFrameParts`. It uses
the product's server flags (`disableTracing`, `disableFatalDefects`), client
ping timeout/retry settings, and actual `withOutputWindow` wrapper. TestClock
advances keep-alive time; deferred values and queues coordinate the scenarios.
No listening server, credentials, product state, or sleeps are involved.
Trace ids and interrupting fiber ids are runtime-generated and change on
regeneration. Request ids start at zero in each isolated fixture. Recorded
actions describe application input. Server frames come from Effect; edge
scenarios also inject intentionally malformed or foreign client frames.

Twenty-four transcripts cover unary success, typed failure, defect, stream end,
mid-stream failure, unary and stream interruption, concurrent calls, ping/pong,
withheld ACKs filling count and byte windows, connection loss, discard, EOF,
notifications, string ids, batches, malformed input, unknown methods, inactive
interrupts, server interruptions, multiple causes, ping after EOF and ping timeout.
The Rust replay checks frame bytes and upgrade context, drives both state
machines, and uses independent test handlers for responses. Interrupting fiber
ids are normalized to null when comparing Rust's default execution context.
The async replay compares generated server frames per call, exercises withheld
ACKs, and asserts the cancelled stream's guard id. Cross-request
scheduling is chosen by the replay harness to match the recorded executor;
per-request content, ordering, and ACK gates come from the Rust implementation.
Rust peers repeat the original scenarios over in-memory `futures` channels and
compare both wire taps with the recordings. `tests/effect.rs` invokes the
exporter's `--verify` mode to decode every Rust-generated frame kind with the
installed Effect JSON codec and envelope schema, including rejection controls.
`framing-cases.json` records TypeScript's exact UTF-8 splitting boundaries.

The protocol follows installed Effect 4.1.3 in
`apps/server/node_modules/effect/src/rpc/{RpcMessage,RpcSerialization,RpcClient,RpcServer}.ts`,
the options in `apps/server/src/ws.ts` and
`packages/client-runtime/src/rpc/{session,protocol}.ts`, and the output windows
in `apps/server/src/terminal/OutputProtocol.ts`.

## Wire format

`RpcSerialization.layerJson` sends ordinary JSON in WebSocket **text** messages,
without a newline or JSON-RPC 2.0 wrapper. Its decoder also accepts UTF-8 binary
messages and arrays of envelopes. Outgoing messages are text. `codec::decode`
returns every envelope in a frame; `codec::encode` accepts a single message or
an array. Object key order for messages generated by Effect is preserved by
the serde declarations and `serde_json`'s `preserve_order` feature.

Client messages are `Request`, `Ack`, `Interrupt`, `Ping`, and `Eof`. Server
messages are `Chunk`, `Exit`, `Defect`, `Pong`, and server-originated `Request`.
`ClientProtocolError` is an Effect-local transport diagnostic, exposed as a
type for adapters; it is not emitted as a WebSocket frame. Unknown envelopes
and cause reasons retain their JSON instead of losing future fields.

Requests have `id`, method `tag`, encoded `payload`, and `headers` as an ordered
array of `[name, value]` pairs. Optional `traceId`, `spanId`, and `sampled` carry
tracing; optional `isNotification: true` suppresses replies and `discard: true`
acknowledges handler start with a void exit. Effect's default ids are numeric,
incrementing from zero across clients in a JS runtime; Rust increments per
client. Both preserve received numeric or string ids without coercing one
into the other. Numeric equality and hashing follow JavaScript (`1 == 1.0`,
`-0 == 0`). Callers can supply their own ids and tracing using `Request`.
Notifications receive distinct internal ids on the server.

Success exits contain `value` (void and stream completion encode as `null`).
Failure exits contain a flat `cause` array: `Fail { error }`, `Die { defect }`,
or `Interrupt { fiberId }`. The required fiber id is numeric or null; Rust accepts
an absent input key but always serializes it as null. Defects are already schema-encoded JSON, including any Error
metadata. A per-call `Die` fails that call; a connection-level `Defect` fails
all pending calls. The product disables fatal defects, so ordinary handler
defects use per-call exits. Handler panics that unwind, output-kind faults and
serialization errors become per-call `Die` exits. A panic-abort build (including
the usual WASM target) cannot recover from a Rust panic; handlers should return
`Exit::die` for recoverable faults.

Pings are application messages every 5 seconds, not WebSocket control frames.
At a ping tick, after a ping is outstanding, more than 15 seconds without any
decoded server frame disconnects pending calls. Exactly 15 seconds is allowed.
A delayed first tick sends a ping before declaring a timeout. Any decoded
frame counts as liveness, including held multipart frames' synthetic pongs.

Streams send nonempty chunks. Normal streams wait for one ACK after each
chunk, including before the final exit. `subscribeServerConfig`,
`orchestration.subscribeShell`, and `orchestration.subscribeThread` allow
eight unacknowledged chunks. `terminal.attach` and `terminal.observe` also
stop when charged pending bytes reach 64 KiB (the actual product envelope and
variable-field charging formula is ported). An oversized first chunk is allowed.
ACKs release existing chunks; they do not accumulate credit. There is no
connection-wide request concurrency ceiling in the product's server options.
Duplicate active request ids are ignored. Different requests may interleave;
each request's chunks precede its single exit. `Eof` stops new requests and
drains existing ones; pings and protocol defects still receive replies. Once
drained, a new request starts a fresh logical client on the same socket, as in Effect.

## API

- `Client<P, A, E>`: `start` or `start_request`, `receive`, `acknowledge`,
  `interrupt`, `tick`, `eof`, and `disconnect`; drain `pop_outgoing` and
  `pop_event`. Events identify their call: `Chunk`, `Exit`, or local `Failed`.
  Feed timestamps in monotonic milliseconds. ACK only after accepting an entire
  chunk into a bounded consumer buffer. Disconnect completes every pending call
  in insertion order and drops unsent frames. Interruption completes the local
  call immediately; its eventual remote exit is ignored.
- `Server<P, A, E>`: `register` methods (or override their `WindowPolicy`), feed
  `receive`, and drain `ServerAction::{Dispatch,Cancel,Ended}`. After constructing
  an authorized handler call `started`, then `send_chunk`/`finish` only when
  `can_poll` permits. `disconnect` cancels all active work without sending
  responses to a departed connection. `receive_with_interruptor` optionally
  carries a local execution id; there is no fabricated global fiber counter.
  `set_upgrade_headers(Vec<(String, String)>)` supplies the adapter's HTTP context,
  prepended to each request's headers. `fail_defect` terminates a faulty handler
  even while its stream awaits an ACK.
- `AsyncClient<S, R, P, A, E>`: a public `state` for starting/interrupting calls,
  `flush`, `next_event(ticks, clock)`, and `close`. Supply a frame sink, an input
  stream of `Result<Frame, sink-error>`, monotonic ticks, and a clock closure
  sampled on receipt and tick wakeups (tick values are ignored). A pending tick stream disables timers. It ACKs returned
  chunks when the caller requests another event. Transport errors leave
  per-call failure events available through `state.pop_event`.
  Undecodable Exit/Chunk bodies fail the affected call with `ClientError::Protocol`
  and queue an Interrupt. An uncorrelatable response or malformed JSON fails all
  pending calls with Protocol while leaving the connection usable.
- `AsyncServer<S, R, H, P, A, E>`: register methods on `state`, then `step` or
  `run`. Implement `Handler::handle(Request) -> HandlerOutput`: a local unary
  future returning `Exit`, or a `ResponseStream` of nonempty chunks / terminal
  exits. Stream exhaustion produces a void success exit. Empty producer chunks
  are skipped. Interrupts immediately drop executing futures and parked streams;
  no subsequent poll is required for cleanup. Connection termination drops all
  handlers. Wrappers use local futures, usable with native local executors and
  browser executors; they do not spawn tasks or require `Send`.
- `framing::{split, Joiner}`: the product's opt-in 48 KiB UTF-8 text frame parts,
  prefixed U+001E except the last part. Binary messages pass through. Write each
  split sequence without interleaving. Async clients join parts automatically;
  call `AsyncServer::set_frame_parts(true)` only for a negotiated peer.

Each connection owns fresh state. Schema decoding/validation belongs in the
handler boundary, and callers must pass already encoded success/error/defect
values matching the method's Effect JSON codecs.

## Connection-layer responsibilities

The HTTP upgrade authenticates before this protocol runs, with cookies or scoped
RPC WebSocket tickets and any DPoP proof. It checks `orchestrationProtocol=2`
(otherwise HTTP 426), advertises client capabilities, and negotiates `frameParts`.
Set `server.state.set_upgrade_headers(...)` from the authenticated upgrade.
Session
expiry/revocation closes sockets. Scope checks remain authoritative server-side.

Product sessions disable Effect's automatic socket retry. The connection
supervisor selects/authenticates a fresh route and constructs a fresh session.
In-flight mutations fail rather than being replayed. Subscriptions must be
reestablished using their domain-specific snapshot/cursor replay and pruning-gap
fallback; an RPC request id is not a subscription resume token.

WebSocket control frames, close codes, compression (`perMessageDeflate: true`),
upgrade deadlines and route/relay management belong to the transport adapter.
`AsyncServer` enforces `transport::MAX_INCOMING_FRAME_BYTES` (100 MiB, matching
the Node server's unmodified `ws` default) before JSON parsing; excess input
returns `TransportError::Io` describing the size limit and cancels active calls. The adapter
should also enforce this before allocating a complete frame and close with 1009.
Plain JSON serialization and the product's multipart joiner have no additional
buffer limit. The product sets no concurrent-call ceiling, so this crate does
not impose one. Per-call pending chunks are capped at one or eight, with the
terminal 64 KiB threshold (one oversized first chunk is allowed). The terminal producer's 8 MiB
queue and resync/overflow behavior are service concerns, separate from the
ported ACK byte window. Malformed JSON produces a Defect reply and reading
continues. Binary input uses replacement UTF-8 decoding, matching TextDecoder.
Defect diagnostic text uses serde's parser errors rather than V8 error metadata.
The sans-I/O `Server::receive` accepts decoded messages; raw input limits belong
to `AsyncServer` or the adapter feeding that state machine.

## Verification

From `rust/`, with the dedicated target directory set for every Cargo command:

```powershell
$env:CARGO_TARGET_DIR = 'C:\Users\Administrator\t3code-rust\rust\target\agents\t3-rpc'
cargo fmt -p t3-rpc --check
cargo clippy -p t3-rpc --all-targets -- -D warnings
cargo test -p t3-rpc
cargo check -p t3-rpc --target wasm32-unknown-unknown
```
